执行中崩溃而没有完成收据的命令，无法保证外部副作用是否发生。Agent 明确报告“结果无法确认”，要求检查实例后重新操作；不会伪装成功，也不会盲目重复执行。

预发布补修：本机 `frps verify` 在启动前执行，现与启动流程一样先修复旧文件缺失的执行位。二进制缺失或路径为目录时提前失败并保持原配置；实际执行仍报 permission denied 时补充权限及 noexec 挂载提示。此修复不解除挂载限制，Docker 数据卷环境仍需单独核对。

## 后续加固

- 登录按来源 IP 限制尝试：15 分钟内最多 10 次，成功登录清除计数。可信代理默认关闭，可使用 `DFPANEL_TRUSTED_PROXIES` 或 `-trusted-proxies` 指定明确 IP/CIDR。
- 登录令牌使用持久化会话编号、明确的 HS256 和 issuer 校验；支持注销当前会话及“退出所有设备”，已注销令牌立即失效。过期会话在登录时清理。
- Agent 普通列表、详情和编辑响应不再序列化 Secret；创建、重置及安装命令保留必要的凭据响应。API 响应禁止缓存。
- 安装命令要求显式 PublicURL，不采用 Host 或转发头推断。校验 HTTP(S)、主机及根路径；分别处理 Bash 参数、PowerShell 单引号与编码命令、Compose 单引号标量。
- HTTP 增加头部读取和空闲期限、头部大小限制，API 正文及 WS 消息限制为 4 MiB。双方 WS 具备读取和写入期限。
- 面板持久日志和本机 frp 日志每秒检查大小，超过 10 MiB 保存尾部副本并截断，保留两份备份。保留原句柄以支持子进程接管；瞬时突发可超过阈值。Agent 自身日志沿用已有轮转。新 Docker/Compose 部署配置 json-file 的 10m/3 份限制。
- 配置版本在事务中分配并有目标/版本唯一约束；同一目标的配置生成、入队和操作顺序一致。旧库如已有同号快照会拒绝迁移并提示核对，保留全部记录，不猜测或自动删除历史。
- 构建最低 Go 版本和 Docker 构建镜像更新为 1.26.9；x/net 更新为 0.60.0，quic-go 为 0.59.1，source-map-js 通过 override 锁定 1.2.2。

## 升级步骤

1. 备份面板数据目录和各 Agent 数据目录，检查正在执行的命令。
2. 从本次源码同时构建面板与 Agent，再统一替换。Docker 面板使用同次构建中内置的 Agent；二进制面板需同时准备新 Agent 分发文件。旧签名直接拒绝，没有兼容开关。
3. 旧登录令牌没有会话编号，升级后需要重新登录。旧库已发送但未确认的普通命令会标为失败并提示核实；可安全重复的 unassign 重新排队。新版已发送命令保留租约恢复能力。
4. 生成安装命令前显式设置 `DFPANEL_PUBLIC_URL` 或 `-public-url`。HTTP 保留兼容；公网部署建议 HTTPS，并限制初始化页面的可访问范围。
5. 反向代理只信任实际代理的 IP/CIDR，避免把任意来源设为可信代理。代理读取超时应覆盖现有应用/回滚等待时间。
6. 已有 Docker 容器需重新创建才能使用日志配额。配置应用、启停、离线补发和历史回滚应在目标部署环境核对一次。
